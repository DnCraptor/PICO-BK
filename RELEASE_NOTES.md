# PICO-BK 1.5.6 — Release notes

Эмулятор БК-0010/0010-01/0011М для RP2040/RP2350.

## Что нового

### Переключение цветности и GrS

- **F12** переключает три режима: **B&W** (монохромный 512×256), **RGB** (цветной 256×256), **GrS** (градации серого, 256×256, 2 бита на пиксель БК). Те же обозначения отображаются в **Home → F2**.
- **VGA RGB222:** серый формируется по палитрам БК; для промежуточной яркости синего используется пространственный дизеринг с чередованием пикселей и строк. Порядок яркостей адаптирован к оригинальной БК-0010: красный ярче зелёного, зелёный ярче синего; белый БК-0011М остаётся отдельным верхним уровнем.
- **TV-soft:** GrS использует собственную яркостную составляющую композитного сигнала без цветовой поднесущей, без дополнительного пиксельного дизеринга.
- **HDMI:** GrS кодируется нативными TMDS-значениями без VGA-ограничения в четыре уровня; таблицы палитр готовятся заранее, вне горячего цикла формирования строк.

### HDMI

- Оптимизировано формирование строк 1024×768: специализированные пути TEXT, B&W и 2bpp, предвыбранные профили кодирования и TMDS-таблицы.
- Общий генератор HDMI clock переведён на PIO; исправлены лишние обращения к Flash из критического пути DMA.
- Исправлена таблица TMDS для палитры №10 в режиме 1024×768 (некорректные нулевые слова вместо части цветов).
- **1024×768 требует разгона RP2350 до 512 МГц**; это режим вне штатных частот микроконтроллера. 720×576 и 800×600 также доступны в HDMI-конфигурациях.

### BIN и оверлеи на SD-карте

- После запуска `.BIN` из файлового менеджера включается перенаправление штатного `EMT 36` на файловую систему SD. Поиск дополнительных файлов выполняется в том же каталоге, из которого запущен BIN.
- Реализованы команды магнитофонного интерфейса: **0** (останов), **1** (пуск), **3** (чтение файла), **4** (фиктивное чтение заголовка без загрузки данных). Команда **2** (запись) остаётся в штатном ПЗУ.
- Поддерживаются запросы по имени, в том числе `.OVL` и `.BIN` для имени без расширения. При отсутствии файла на SD сохраняется штатный путь через ПЗУ.
- При монтировании дискового образа из менеджера перенаправление отключается; дисковый перехватчик продолжает работать отдельно.
- **Home → F2 → NoCatch EMT 36 on BIN:** `false` (по умолчанию) — разрешить; `true` — отключить перенаправление. Параметр хранится в `\BK\bk.conf`, структура снимков `.BKE` не изменена.

## Сборка релизных UF2

В корне репозитория на Windows:

```bat
build_all.bat
build_all.bat --targets m1p2,m2p2 --audio PWM,I2S --video VGA-HDMI
build_all.bat --targets z0p2 --audio PWM --video TV-SOFT --clean
```

По умолчанию: **все 63 комбинации** (7 профилей плат × 3 звука `PWM/I2S/HWAY` × 3 видеорежима `VGA-HDMI/VGA/TV-SOFT`). Для матрицы доступны `--targets`, `--audio PWM,I2S,HWAY`, `--video VGA-HDMI,VGA,TV-SOFT`, `--jobs`, `--clean` и `--dry-run`.

Каждый вариант собирается в отдельном `build-release/…`; готовые UF2, `manifest.csv` и `SHA256SUMS` формируются в `firmware/1.5.5/`. При новом запуске содержимое UF2 в каталоге релиза обновляется под выбранную матрицу, чтобы не включать устаревшие файлы. Сборка продолжается после ошибки отдельного варианта; ошибки записываются в `failures.csv`, а процесс возвращает ненулевой код. `manifest.csv` и `SHA256SUMS` содержат только успешно собранные UF2.

Зависимости: Python 3, CMake, Ninja, arm-none-eabi toolchain и Pico SDK 2.3.1 (как в проекте). Система сборки не изменяет настройки в исходном `CMakeLists.txt` вручную; варианты выбираются `-D`-параметрами.

## Известные ограничения

- Перехват `EMT 36` **не** моделирует последовательное движение ленты и перебор несовпадающих файлов; отдельные программы, рассчитывающие на такой сценарий, могут потребовать штатного магнитофонного драйвера (`NoCatch = true`).
- Поддержка команд записи на «кассету» через файлы SD в этом релизе не реализована.
- 1024×768 критичен к таймингам и стабильности конкретной аппаратной сборки из-за высокой частоты; работоспособность одной комбинации GPIO/платы не является гарантией для остальных.
- Выбор `I2S` или `HWAY` в скрипте создаёт соответствующую программную сборку, но не гарантирует наличие требуемого аудиооборудования на выбранной плате.
