# PICO-BK — эмулятор БК-0010(-01) / БК-0011М для Raspberry Pi Pico и Pico 2

Эмулятор советских домашних компьютеров **БК-0010, БК-0010-01 и БК-0011М** (процессор К1801ВМ1, система команд PDP-11) для микроконтроллеров **RP2040** (Raspberry Pi Pico) и **RP2350** (Raspberry Pi Pico 2). Основная платформа — отладочная плата **[Мурмулятор](https://murmulator.ru)**. Также поддерживаются Olimex RP2040-PICO-PC и Waveshare RP2040/RP2350-PiZero.

Эмулятор основан на [BK8266 (ветка BK0011M)](https://github.com/konst-st/BK8266/tree/BK0011M) — эмуляторе для ESP8266 от konst-st.

## Быстрый старт

1. Выберите прошивку под свою плату (см. [Платы и имена прошивок](#платы-и-имена-прошивок)).
2. Прошейте её: удерживая кнопку BOOT(SEL), подключите плату к компьютеру по USB. Появится диск, скопируйте на него файл `.uf2`. Подробнее — на [murmulator.ru/flash](https://murmulator.ru/flash).
3. Подготовьте SD-карту (FAT32). При первом запуске эмулятор сам создаст каталог `\BK`, образы дисководов `\BK\fdd0.img`–`fdd3.img` и, после настройки, файл `\BK\bk.conf`. В `fdd0.img` и `fdd1.img` записываются встроенные образы (МКДОС и игры). Файлы `.bin`, `.img`, `.bkd` и `.bke` можно класть в любые каталоги карты: их открывает файловый менеджер (**Home**).
4. Если после изменения настроек эмулятор не запускается, при включении держите **Пробел**: файл конфигурации будет пропущен.

## Платы и имена прошивок

Имя файла прошивки устроено так:

```
<плата><чип>-bk-<видео>-<частота>-<звук>-<версия>.uf2
например: m2p2-bk-VGA-HDMI-400MHz-I2S-1.5.6.uf2
```

Первые четыре символа — **префикс**: разводка платы (`m1`, `m2`, `PC`, `z0`) и чип (`p1` — RP2040, Raspberry Pi Pico или совместимая плата; `p2` — RP2350, Raspberry Pi Pico 2 или совместимая).

| Префикс | Плата | Микроконтроллер |
|---|---|---|
| `m1p1` | **Мурмулятор 1.x** и платы с той же распиновкой: [классическая схема AlexEkb](https://github.com/AlexEkb4ever/MURMULATOR_classical_scheme), Мурмулятор Ultimate, самодельные сборки ([варианты](https://murmulator.ru/types)) | RP2040 — Raspberry Pi Pico или совместимая |
| `m1p2` | то же | RP2350 — Raspberry Pi Pico 2 или совместимая |
| `m2p2` | **Мурмулятор 2.0** или совместимая плата | RP2350 — Raspberry Pi Pico 2 или совместимая |
| `PCp1` | **[Olimex RP2040-PICO-PC](https://www.olimex.com/Products/MicroPython/RP2040-PICO-PC/)** (VGA, DVI/HDMI, звук на 3,5 мм, microSD) | RP2040 (Pico / RP2040-PICO30) |
| `PCp2` | Olimex RP2040-PICO-PC с модулем Pico 2 | RP2350 |
| `z0p1` | **[Waveshare RP2040-PiZero](https://www.waveshare.com/product/raspberry-pi/boards-kits/rp2040-pizero.htm)** (форм-фактор Raspberry Pi Zero, mini-HDMI, microSD) | RP2040 |
| `z0p2` | **[Waveshare RP2350-PiZero](https://www.waveshare.com/wiki/RP2350-PiZero)** | RP2350B |

Остальные части имени:

| Часть | Значение |
|---|---|
| `VGA-HDMI` | VGA или HDMI. Выход определяется автоматически при старте по разводке выводов. |
| `VGA` | только VGA |
| `TV` | композитный выход PAL на ЭЛТ-телевизор (программный, через резисторную ЦАП-матрицу VGA-выхода) |
| `390MHz` / `400MHz` / `319.2MHz` | системная частота микроконтроллера: RP2040 / RP2350 для VGA и HDMI, TV. Для HDMI частоту задаёт выбранный режим (см. [Видео](#видео)). |
| `PWM` | звук ШИМ-сигналом на выводы платы (RC-фильтр) |
| `I2S` | внешний I2S-ЦАП (TDA1387, PCM5102A и т.п.) |
| `HWAY` | «железный» TurboSound: два AY-3-8910/YM2149 через сдвиговый регистр 74HC595 (см. [Звук](#звук)) |

Замечания:

- Платы Waveshare PiZero всегда выводят изображение на HDMI. Варианты `VGA` для них ничем не отличаются от `VGA-HDMI`.
- На Olimex RP2040-PICO-PC I2S не разведён, для неё нужна прошивка `PWM`.
- `HWAY` рассчитан на распиновку Мурмулятора 1.x (GP26–28 и тактовые выходы GP21/GP29).
- Наличие варианта в релизе не означает, что проверены все сочетания платы и звукового оборудования.

## Видео

- **VGA**, режим 1024×768 60 Гц. Чёрно-белый режим БК (512×256) выводится с удвоением точек и утроением строк, цветной (256×256) — с учетверением точек и утроением строк. Рекомендуется формат монитора 4:3.
- **HDMI**, режим задаётся параметром `dvi_mode` (Home → F2):
  - `0` — 720×576 50 Гц (270 МГц), по умолчанию;
  - `1` — 800×600 60 Гц (400 МГц);
  - `2` — 1024×768 60 Гц, только RP2350, требует разгона до 512 МГц и поддержки монитором нестандартных режимов.

  Изображение выводится с полями. Пропорции пикселей HDMI и БК не совпадают, поэтому монитор лучше переключить в 16:9. На RP2040 HDMI работает нестабильно.
- **TV**: композитный PAL 50 Гц.

Режимы цветности (**F12** по кругу; в настройках — `color_mode`):

- **B&W** — монохромный 512×256;
- **RGB** — цветной 256×256;
- **GrS** — градации серого 256×256, два бита на пиксель БК. На VGA промежуточная яркость синего получается пространственным дизерингом, на HDMI используются отдельные TMDS-таблицы, на TV — только яркостная составляющая. Порядок яркостей как у БК-0010: красный ярче зелёного.

## Звук

- Пищалка (бипер) и моно-Covox на порту 177714. Covox гибридный: основная часть — моно на штатном регистре параллельного порта с loopback, а также стерео-вариант на наборе регистров AZБК (без ПДП).
- Программный AY-3-8910 в варианте БК TurboSound на одном чипе (моно).
- «Железный» TurboSound на двух AY-3-8910 (или совместимых) в прошивках `HWAY`: один чип работает как AY, второй — как Covox и бипер. Подключение по распиновке Мурмулятора 1.x: сдвиговый регистр 74HC595 на GP26 (LATCH), GP27 (CLK), GP28 (DATA), тактирование AY с GP21/GP29.
- Обратная «шипелка» при загрузке с магнитофона (вход LOAD, см. ниже) подмешивается к звуку.

## Периферия

- **Клавиатура PS/2 или USB**. USB-клавиатура подключается к разъёму USB платы (через OTG-адаптер или хаб). Русские буквы и спецсимволы перекодируются автоматически.
- **Джойстики** (биты порта 177714, см. [Джойстики](#джойстики)):
  - Dendy (NES) — один или два;
  - USB-геймпады:
    - XInput (Xbox 360 / Xbox One и совместимые);
    - HID-геймпады и джойстики: SNES-подобные, DualShock 4, DualSense, Logitech F710 в режиме «D», клоны 2563:0575, FEED:2320 и 0810:0001.

    USB-геймпады работают как джойстик №1 вместе с Dendy и включаются тем же параметром `is_dendy_joystick`.
  - эмуляция двух джойстиков клавишами клавиатуры (Num Lock, `is_kbd_joystick`);
  - Wii-контроллер по I²C — только в прошивках, собранных с `-DUSE_WII=ON`, в релизные не входит.
- **SD-карта**: файловый менеджер, образы дисков, снимки состояния, конфигурация.
- **Загрузка с магнитофона**: звуковой сигнал подаётся на вход LOAD (GP22 у Мурмуляторов 1.x и 2.0, GP5 / UXT1-10 у Olimex PICO-PC, GP17 у PiZero) и читается программой БК как вход магнитофона. Пример — на [murmulator.ru/pico-bk](https://murmulator.ru/pico-bk).
- **Таймер БК-0010** (регистры 177706, 177710, 177712) и прерывание по вектору 0100 от таймера БК-0011М (50 Гц).
- **КНГМД** на 4 дисковода: образы `.img`/`.bkd` на SD-карте.

## Эмулятор К1801ВМ1

Ядро взято из [BK8266](https://github.com/konst-st/BK8266/tree/BK0011M), кое-что подсмотрено в эмуляторе Юрия Калмыкова [gid.pdp-11.ru](http://gid.pdp-11.ru). Процессор работает в режиме К1801ВМ1 (без «Г»). Эмулируется частота 3 МГц для БК-0010 и 4 МГц для БК-0011М.

Используется только встроенное ОЗУ RP2040/RP2350, из него 128 КБ отдано под ОЗУ БК-0011М; внешняя PSRAM не нужна. ПЗУ (монитор БК-0010, БОС, Бейсик и Фокал БК-0011М) хранятся во Flash.

Режимы эмуляции (**F11** в менеджере или `mode` в `bk.conf`):

| `mode` | Конфигурация |
|---|---|
| 0 | БК-0010 + КНГМД 16 К (после сброса клавиатурный скрипт сам набирает `S160000` и Enter) |
| 1 | БК-0010 + Фокал + МСТД |
| 2 | БК-0010-01 + Вильнюс Бейсик 86 |
| 3 | БК-0011М + Бейсик Экситон + КНГМД |
| 4 | БК-0011М + МСТД |

Пока не реализовано: прерывание по вектору 14 после каждой команды при установленном в PSW бите T (трассировка).

### Запуск BIN и перехват EMT 36

- При запуске `.bin` из файлового менеджера программа загружается в ОЗУ по адресу из заголовка. Если адрес ниже 01000, это автостарт.
- Эмулятор заполняет системные ячейки так, как это делает команда `M` монитора после загрузки с магнитофона:
  - блок параметров EMT 36 по адресу 0320;
  - найденные адрес (0346), длину (0350) и имя (0352);
  - адрес и длину последней загрузки (0264/0266).

  На эти ячейки полагаются некоторые программы: например, загрузчик Lode Runner 2 копирует себя по длине из 0350.
- **Перехват EMT 36.** После запуска `.bin` магнитофонные запросы программы обслуживаются с SD-карты, из каталога, где лежит этот `.bin`:
  - поддерживаются команды 0 (останов), 1 (пуск), 3 (чтение), 4 (фиктивное чтение);
  - для имени без расширения пробуются варианты `.OVL` и `.BIN`;
  - если файла на SD нет, запрос уходит в штатное ПЗУ;
  - запись на «кассету» (команда 2) идёт через ПЗУ;
  - последовательное движение ленты не эмулируется;
  - при монтировании образа диска перехват выключается;
  - отключить его можно в Home → F2 → «NoCatch EMT 36 on BIN» (`no_catch_emt36_on_bin`).

## Конфигурационный файл `\BK\bk.conf`

Файл создаётся из настроек (Home → F2), строки имеют вид `параметр:значение`.

| Параметр | Значения |
|---|---|
| `mode` | режим эмуляции 0–4 (см. [таблицу](#эмулятор-к1801вм1)) |
| `is_covox_on` | 0/1 |
| `is_AY_on` | 0/1 |
| `color_mode` | 0 — B&W, 1 — RGB, 2 — GrS |
| `snd_volume` | −16…5 |
| `graphics_pallette_idx` | палитра 0–15 |
| `is_swap_wins_enabled` | 0/1, по умолчанию 1 (оба Win переключают язык по кругу) |
| `is_dendy_joystick` | 0/1 — Dendy- и USB-джойстики. При включении выключается Covox-loopback (не сам Covox): они используют один порт. |
| `is_kbd_joystick` | 0/1 — эмуляция джойстиков клавишами (Covox-loopback выключается). Включённый Dendy-джойстик перебивает эмуляцию. |
| `kbdpad1_A` … `kbdpad2_RIGHT` | клавиши эмуляции джойстиков №1/№2 (A, B, START, SELECT, UP, DOWN, LEFT, RIGHT) — скан-коды PS/2 набора 1 в десятичном виде |
| `manager_pallette_idx` | 0 — тёмная схема файлового менеджера, 1 — цветная |
| `is_128_48` | 0/1 — мелкие буквы в файловом менеджере (только VGA) |
| `dvi_mode` | только HDMI: 0 — 720×576 50 Гц (270 МГц), 1 — 800×600 60 Гц (400 МГц), 2 — 1024×768 60 Гц (512 МГц, только RP2350) |
| `is_8x8` | 0/1 — шрифт 8×8 вместо 8×16 |
| `no_catch_emt36_on_bin` | 0/1, по умолчанию 0 — запретить перехват EMT 36 для запущенных BIN |

## Сборка

Нужны **Python 3, CMake ≥ 3.22, Ninja, ARM GNU toolchain и Pico SDK 2.3.1** (в Windows подойдут инструменты расширения Raspberry Pi Pico для VS Code). Если CMake или Ninja нет в `PATH`, скрипт ищет их в `%USERPROFILE%\.pico-sdk`. Переопределить пути можно переменными окружения `CMAKE`, `NINJA`, `PICO_SDK_PATH`.

Релизный комплект собирает `build_all.bat` (или `python tools/build_all.py`):

```bat
build_all.bat
build_all.bat --targets m1p2,m2p2 --audio PWM,I2S --video VGA-HDMI
build_all.bat --targets z0p2 --audio PWM --video TV-SOFT --clean
build_all.bat --dry-run
```

Без аргументов собирается полная матрица из 63 вариантов: 7 плат (`m1p1`, `m1p2`, `m2p2`, `PCp1`, `PCp2`, `z0p1`, `z0p2`) × 3 варианта звука (`PWM`, `I2S`, `HWAY`) × 3 видеовыхода (`VGA-HDMI`, `VGA`, `TV-SOFT`).

- `--targets`, `--audio` и `--video` принимают `all` или список через запятую;
- `--jobs N` задаёт параллелизм, `--clean` удаляет каталоги выбранных сборок, `--dry-run` показывает команды без сборки;
- каждый вариант собирается в своём каталоге `build-release/<плата>-<видео>-<звук>`;
- готовые `.uf2`, `manifest.csv` и `SHA256SUMS` складываются в `firmware/<версия>/`, версия берётся из `BUILD_VERSION` в `CMakeLists.txt`; при следующем запуске набор UF2 там заменяется выбранной матрицей;
- ошибка одного варианта не прерывает остальные: неудачные записываются в `failures.csv`, код завершения ненулевой.

Одиночная сборка через CMake. Параметры по умолчанию: Мурмулятор 2.0, I2S, VGA/HDMI.

```sh
cmake -S . -B build -DPICO_BOARD=pico2 -DPICO_PLATFORM=rp2350-arm-s \
      -DMURM2=ON -DAY_TYPE=I2S -DVGA_ONLY=OFF -DTV_OUT=OFF
cmake --build build
```

| Параметр | Значение |
|---|---|
| `-DMURM2` / `-DPICO_PC` / `-DZERO` / `-DZERO2` | разводка платы: Мурмулятор 2.0 / Olimex PICO-PC / Waveshare RP2040-PiZero / Waveshare RP2350-PiZero; все OFF — Мурмулятор 1.x |
| `-DPICO_BOARD=pico\|pico2` и `-DPICO_PLATFORM=rp2040\|rp2350-arm-s` | чип (для `ZERO2` выбираются автоматически) |
| `-DAY_TYPE=PWM\|I2S\|HWAY` | звук |
| `-DVGA_ONLY=ON` / `-DTV_OUT=ON` | только VGA / композитный TV |
| `-DUSE_WII=ON` | поддержка Wii-контроллера |

Прошивка появится в `bin/Release/`. Linux-версия для ARM64 (Orange Pi Zero 2W, DRM/KMS + ALSA) живёт в ветке [`orange`](https://github.com/DnCraptor/PICO-BK/tree/orange).
